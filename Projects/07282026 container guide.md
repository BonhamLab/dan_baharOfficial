### Introduction to Containers
A container is a mini-computer within your computer that contains its own mini-Linux. A container is composed of the exact versions of every library that the program depends on, its own package managers, and its own channels. Therefore, when you build a container, it will behave consistently in different locations, whether on dogen or on your local computer. Previously (link here), we encountered dependency-mismatch issues, which are now resolved because we have finally found a working setup. In other words, we were able to capture a frozen-in-time snapshot of a working environment, called an image, that behaves the same way wherever you run it.

Docker is a container engine, which you will need to download [here](https://docs.docker.com/desktop/setup/install/mac-install/). Docker can build images from a Dockerfile (reciepe to build images), and it can run containers based on these images. Importantly, Docker runs on a service called daemon, which only runs with admin privileges that only Kevin (the administrator) has. Therefore, while you cannot run Docker on dogen, you can run it on your local computer.

Podman is another container engine. It can also build images and run containers based on images and Dockerfiles, with the exact same commands as Docker. The main difference is that Podman lacks daemon, which means you do not need admin privileges to use it. One other difference is that Podman requires an extra flag on the build command, `--format=docker` which tells Podman to produce an image in the same format that Docker uses. In short, Podman pretends to be Docker, and you must add `--format=docker` when building.
